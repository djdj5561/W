校园办事指南助手

遇到校园事务时，直接问一句，助手就能帮你找到流程、材料和办理地点，还能整理成一份待办清单。

本次演示使用：Ollama + Qwen2.5 7B + Streamlit + Python Tool Calling

1. 项目定位与用户问题

谁会用

需要办理教务、证件、宿舍或网络业务的在校学生。

怎么用

不用记功能名称，直接问一句：“校园卡丢了，需要准备什么？”

它解决什么

把分散的办事信息集中到一个入口，减少找错部门、漏看材料的情况。

会得到什么

系统会给出清楚的步骤、材料、办理地点和可以下载的清单。

说明：当前使用的是课程演示数据，实际办理仍要以学校最新通知为准。

2. 系统架构与数据流

用户提问→Qwen2.5 7B→选择工具→查询指南→返回结果

模型负责理解

模型先听懂用户想办什么，再决定需要查询哪一类事项。

程序负责执行

程序按照固定的业务工具查询信息，不让模型直接操作系统。

指南负责提供内容

指南文件中保存着事项、关键词、步骤、材料、部门和地点。

页面负责呈现

网页把结果整理出来，并提供清单下载和提交前确认。

3. 当前可查询的 8 类事项

教务与学籍｜学生请假申请请假流程、证明材料和缺课处理
图书馆服务｜借阅证补办挂失、核对记录和重新办证
校园生活｜校园卡挂失与补办先挂失，再核对余额和办理补卡
校园生活｜宿舍报修填写故障情况，必要时补充照片
教务与学籍｜成绩单与在读证明了解线上或线下打印方式
网络与信息化｜校园网服务处理开通、断网和认证失败
学生资助｜奖助学金申请查看申请表、材料和审核流程
校园生活｜失物招领登记登记遗失或拾到的物品

以后想增加新事项，只要补充一条指南内容即可。

4. 四个业务工具的职责

search_guides

先根据用户的关键词，找到可能相关的办事事项。

get_requirements

再把这个事项的步骤、材料、部门和地点查完整。

build_checklist

把查询结果整理成可以下载和保存的办事清单。

submit_application

在用户确认后生成一个本地演示编号，不会提交真实申请。

简单来说：前面三个工具负责查询和整理，最后一个工具负责演示提交。

5. 关键代码：工具注册表与分发器

TOOL_REGISTRY = { "search_guides": search_guides, "get_requirements": get_requirements, "build_checklist": build_checklist, "submit_application": submit_application, } def execute_tool(call: ToolCall) -> Any: if call.name not in TOOL_REGISTRY: raise ValueError(f"未知工具：{call.name}") return TOOL_REGISTRY[call.name](**call.arguments)

逐行理解

TOOL_REGISTRY 是工具白名单；键是模型返回的名称，值是 Python 函数。

call.arguments 保存模型给出的参数；** 将字典展开为关键字参数。

安全作用

模型只能调用注册过的 4 个业务函数。未知名称直接抛出错误，避免任意执行代码。

6. 关键代码：真实模型接入

load_dotenv(Path(__file__).parent / ".env") client = OpenAI( api_key=api_key, base_url="http://localhost:11434/v1", timeout=120.0, max_retries=1, ) response = client.chat.completions.create( model="qwen2.5:7b", messages=messages, tools=tools, tool_choice="auto", )

配置

Ollama 在本机提供 OpenAI 兼容接口，模型名称为 qwen2.5:7b，不需要云端 Token。

模型职责

模型负责理解自然语言、选择工具、填写参数；业务数据和函数仍由项目代码控制。

7. 一次提问的完整执行过程

  1. 用户输入：“校园卡挂失补办需要什么？”
  2. 模型先判断这是校园卡相关的问题。
  3. 系统找到对应的指南，并读取具体步骤和材料。
  4. 如果用户需要清单，系统会继续把内容整理成文件。
  5. 最后，页面展示办理信息，并提供下载按钮。
用户只需要负责提问，模型负责理解，程序负责把可靠的指南内容整理出来。

8. 现场演示脚本

第一步：打开应用

cd campus-guide-assistant python -m streamlit run app.py

第二步：提出问题

“我想办理校园卡挂失补办，需要准备什么？”

第三步：查看结果

页面会显示校园卡办理步骤、所需材料、办理部门和地点。

第四步：保存清单

点击 Markdown 或 HTML 下载，把结果保存下来，之后照着清单办理即可。

演示提醒：本地 7B 模型第一次回答可能需要等待一会儿。

9. 遇到问题时怎么处理

模型只找到事项

有时模型只完成第一步搜索，程序会根据找到的事项继续补充详细流程和清单。

没有额外配置

项目已经准备了默认设置，直接使用本机 Ollama 也能启动。

回答等待时间较长

本地模型第一次回答会慢一些，程序设置了等待和重试，避免页面一直卡住。

模型服务没有启动

页面会告诉用户检查 Ollama、模型名称和端口，方便定位问题。

10. 使用边界与安全说明

目前不会做什么

  • 不连接真实学校系统
  • 不提交真实申请
  • 不保存真实学号、手机号或账号密码
  • 不把个人配置上传到仓库

为什么要确认

用户点击“提交模拟申请”后，系统还会再确认一次。

没有勾选确认时不会提交；确认后只生成一个本地演示编号。

页面中的指南是课程演示内容，实际办理前请以学校最新通知为准。

11. 项目总结与交付内容

提出问题→助手理解→查询指南→得到答案→保存清单

这个项目能做什么

学生用一句话描述需求，系统就能给出对应的校园办事信息和办理清单。

最终效果

把原本分散的流程、材料和地点整理到一起，让校园办事更容易查、更容易准备。

一句话总结：这是一个帮助学生快速找到校园办事流程的智能助手。
