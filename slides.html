校园办事指南助手

用自然语言查询校园事务流程，生成材料清单，并在确认后创建本地模拟申请。

姓名：王文静　学号：f25015415

1. 用户与要解决的问题

用户

需要办理校园事务的学生。

痛点

流程分散、材料不清楚、容易遗漏下一步。

项目目标

用户只需要说一句话，系统就能返回办理部门、地点、步骤、材料，并生成可以带走的清单。

示例：“我想办理校园卡挂失补办，需要准备什么？”

2. 项目总体架构

自然语言输入 → Streamlit 界面 → Agent 规划 → 工具注册表 → 本地指南数据 → 结果与文件

界面层

app.py：输入框、结果展示、调用日志、下载按钮。

业务层

tools.py：搜索、读取详情、生成清单、模拟提交。

数据层

data/guides.json：结构化办事指南示例数据。

模型层

理解用户需求，规划工具调用顺序，并组织最终回答。

3. 四个业务工具

search_guides

按中文关键词搜索指南，返回候选事项。

get_requirements

读取指定事项的步骤、材料、部门和地点。

build_checklist

生成 Markdown 和 HTML 办事清单。

submit_application

仅在用户确认后创建本地模拟申请，不访问真实系统。

四个工具均在 tools.py 中注册并由统一分发函数执行。

4. 关键代码逐行解释：工具注册与分发

TOOL_REGISTRY: dict[str, Callable[..., Any]] = {建立工具注册表；键是工具名，值是对应 Python 函数。类型注解表示字符串映射到可调用对象。
"search_guides": search_guides,把搜索工具名称映射到搜索函数。
"get_requirements": get_requirements,把详情查询工具名称映射到详情函数。
"build_checklist": build_checklist,把清单生成工具名称映射到清单函数。
"submit_application": submit_application,把模拟提交名称映射到带确认检查的函数。
}注册表结束；新工具需实现函数后在这里登记。
def execute_tool(call: ToolCall) -> Any:定义统一分发入口；call 带有工具名和参数字典，返回类型可因工具而异。
if call.name not in TOOL_REGISTRY:检查工具是否在白名单注册表中。
raise ValueError(f"未知工具：{call.name}")不在注册表就报错并说明未知名称，避免调用不存在的工具。
return TOOL_REGISTRY[call.name](**call.arguments)按名称取函数；** 把参数字典展开为关键字参数并执行，返回函数结果。

对应真实代码：tools.py 中的 TOOL_REGISTRY 和 execute_tool。

5. 项目目录与数据结构逐行解释

目录项作用

app.py应用入口：界面、规划、调用工具和显示结果。
tools.py业务函数、注册表和工具分发器。
data/guides.json存放程序读取的示例指南。
requirements.txt声明 Python 运行依赖。
.env.example示范可选模型变量，不含真实 Key。
README.md安装、运行和答辩说明。
slides.html本次汇报幻灯片。

JSON 字段逐行作用

{开始一条指南对象。
"id": "card",唯一编号，用于工具之间定位同一条记录。
"title": "校园卡挂失与补办",事项的用户可见名称。
"steps": [...],办理步骤数组，按顺序展示。
"materials": [...],所需材料数组，生成待办清单。
"department": "一卡通服务中心"告诉用户应该联系哪个部门。
}结束这一条指南对象。

数据和代码分离：更新办事内容时改 JSON，不必重写工具函数。

6. 一次请求中每个步骤的作用

用户输入校园卡问题Streamlit 收到问题文本；例如“我想办理校园卡挂失补办，需要准备什么？”
规划器 / model_run分析问题，确定要调用的工具以及每个工具所需的参数。
ToolCall(name, arguments)把工具名称和参数放入一个对象，例如 search_guides 与用户问题。
execute_tool(search_guides)搜索函数在 guides.json 中匹配并返回候选指南。
execute_tool(get_requirements)用候选指南的 id 读取步骤、材料、部门和地点。
execute_tool(build_checklist)把指南内容整理成 Markdown，并提供 Markdown/HTML 下载。
render_result + history把结果呈现在页面；history 保存调用和结果，让右侧日志能显示本次运行过程。

若用户点击“提交模拟申请”，界面先要求勾选确认；未确认时不执行 submit_application。

8. 现场演示步骤

  1. 启动项目：python -m streamlit run app.py
  2. 输入：“我想办理校园卡挂失补办，需要准备什么？”
  3. 观察右侧调用日志：搜索、详情、清单。
  4. 查看办理步骤和材料。
  5. 下载 HTML 清单。
  6. 不勾选确认时点击提交，系统拒绝；勾选后才生成本地模拟编号。
演示数据是虚构数据，不展示真实学号、手机号或校园账户。

9. 异常处理与安全边界

找不到指南

返回“暂时没有匹配到指南”，提示用户换关键词，不编造流程。

未知工具

execute_tool 检查工具名，不在注册表中的调用直接报错。

未确认提交

submit_application 检查 confirmed，未确认时抛出权限错误。

模型不可用

自动回退本地演示规划器，保证课堂主路径仍可运行。

11. 模型接入方式

本地模型

可通过 Ollama 运行通义千问等模型，由模型理解问题并生成 ToolCall。

兼容接口

也支持 OpenAI 兼容接口，在 .env 中配置接口地址和模型名称，执行多轮 Tool Calling。

模型负责理解需求和规划调用，业务工具负责查询指南、生成清单和执行确认后的模拟提交。

12. 思政、评分点与后续改进

  • 服务于校园治理和学生办事的正当需求。
  • 使用虚构指南和样例数据，不采集过度隐私。
  • 工具真正被调用，且有可见日志和文件产出。
  • README 可复现，PPT 可解释，现场可走通主路径。
  • 后续可接入官方公开指南、增加版本管理、长期记忆和只读业务 API。
