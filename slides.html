校园办事指南助手

用真实大模型理解校园事务，查询结构化指南，生成办理清单，并在确认后创建本地模拟申请。

姓名：王文静　学号：f25015415

当前演示配置：Ollama + Qwen2.5 7B + Streamlit + Python Tool Calling

1. 项目定位与用户问题

使用者

需要办理教务、证件、校园生活或信息化服务的学生。

输入方式

直接说一句自然语言，例如“校园卡丢了，需要准备什么？”

解决的问题

流程分散，材料不清楚，学生容易漏掉下一步或找错办理部门。

输出结果

返回事项说明、办理步骤、所需材料、部门地点和可下载清单。

设计边界：指南数据使用课程演示样例，真实办理仍以学校最新公告为准。

2. 系统架构与数据流

自然语言问题→Qwen2.5 7B→Tool Calling→校园指南数据→步骤与清单

模型层

model_run() 向 Ollama 发送问题和工具定义，模型决定先搜索哪类事项。

业务层

tools.py 只执行白名单函数，保证模型不能随意调用系统操作。

数据层

data/guides.json 存储事项标题、关键词、步骤、材料、部门和地点。

界面层

Streamlit 负责输入、结果展示、清单下载和提交前确认。

3. 当前可查询的 8 类事项

教务与学籍｜学生请假申请病假、事假、缺课处理与证明材料
图书馆服务｜借阅证补办挂失、异常记录核对与补证
校园生活｜校园卡挂失与补办挂失、余额检查与补卡绑定
校园生活｜宿舍报修故障描述、照片和维修工单
教务与学籍｜成绩单与在读证明电子或线下证明申请
网络与信息化｜校园网服务开通、断网、认证失败申报
学生资助｜奖助学金申请申请表、材料和审核环节
校园生活｜失物招领登记遗失或拾取物品登记与领取

增加事项只需在 JSON 中新增一条指南记录，工具函数无需改写。

4. 四个业务工具的职责

search_guides

按用户问题匹配关键词，返回最多 3 条候选指南。

get_requirements

根据指南编号读取步骤、材料、部门、地点和提示。

build_checklist

把指南整理成 Markdown，并转换成可下载的 HTML 文件。

submit_application

检查 confirmed 参数，只创建本地模拟编号，不连接学校系统。

权限边界：查询和生成清单可以直接执行；模拟提交必须由用户勾选确认。

5. 关键代码：工具注册表与分发器

TOOL_REGISTRY = { "search_guides": search_guides, "get_requirements": get_requirements, "build_checklist": build_checklist, "submit_application": submit_application, } def execute_tool(call: ToolCall) -> Any: if call.name not in TOOL_REGISTRY: raise ValueError(f"未知工具：{call.name}") return TOOL_REGISTRY[call.name](**call.arguments)

逐行理解

TOOL_REGISTRY 是工具白名单；键是模型返回的名称，值是 Python 函数。

call.arguments 保存模型给出的参数；** 将字典展开为关键字参数。

安全作用

模型只能调用注册过的 4 个业务函数。未知名称直接抛出错误，避免任意执行代码。

6. 关键代码：真实模型接入

load_dotenv(Path(__file__).parent / ".env") client = OpenAI( api_key=api_key, base_url="http://localhost:11434/v1", timeout=120.0, max_retries=1, ) response = client.chat.completions.create( model="qwen2.5:7b", messages=messages, tools=tools, tool_choice="auto", )

配置

Ollama 在本机提供 OpenAI 兼容接口，模型名称为 qwen2.5:7b，不需要云端 Token。

模型职责

模型负责理解自然语言、选择工具、填写参数；业务数据和函数仍由项目代码控制。

7. 一次提问的完整执行过程

  1. 用户输入“校园卡挂失补办需要什么”。
  2. Qwen2.5 根据工具描述生成 search_guides 调用。
  3. 程序在指南库中找到 card 记录。
  4. 如果模型提前结束，程序根据已选指南补齐 get_requirements。
  5. 问题包含“需要、材料、清单”等意图时，继续生成 build_checklist。
  6. 页面展示步骤和材料，并提供 Markdown、HTML 下载。
模型负责理解，程序负责执行和校验。这样既体现 AI，又避免模型凭空编造办事内容。

9. 异常处理与本次修复

模型只返回搜索

部分本地模型不会连续调用详情工具。程序现在会读取模型选中的指南，再补齐详情和清单步骤。

配置文件未加载

Ollama 地址、API 占位值和模型名都有代码默认值，.env 仍可覆盖配置。

请求时间过长

客户端设置 120 秒超时并允许 1 次重试，避免界面无限等待。

模型服务不可用

页面显示具体错误，提示检查 Ollama 服务、模型名称和端口，不再静默切换到旧模式。

10. 安全边界与数据合规

当前不会做的事

  • 不访问真实学校系统
  • 不提交真实申请
  • 不保存真实学号、手机号或账号密码
  • 不把 .env 和模型配置上传到仓库

提交确认机制

用户点击“提交模拟申请”后，系统先检查确认框。

未确认时抛出 PermissionError；确认后只生成 DEMO-... 本地编号。

所有指南均为课程演示样例，真实办理前必须核对学校最新通知。

11. 项目总结与交付内容

自然语言理解→真实模型规划→业务工具执行→中文结果→文件产出

项目文件

app.py 负责页面和模型请求；tools.py 负责业务函数和权限检查；data/guides.json 保存 8 类事项。

完成情况

完成自然语言、Tool Calling、业务操作和 WebUI 闭环。结果可解释、可下载，敏感操作有确认机制。
